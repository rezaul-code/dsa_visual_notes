Introduction to Data Structures

Core concepts: Data Structures, Abstract Data Types, and Algorithm fundamentals — the foundation of everything in DSA.

Data Structure

A method of arrangement in memory to hold data associated with objects to facilitate access and operations on the data.

Abstract Data Type (ADT)

Describes arrangement of data without specifying how it is stored or accessed in memory. Examples: Stack, Queue, Tree.

Algorithm

A method that solves a computational problem in a finite number of steps. Consumes time and memory resources.

Primitive vs Abstract Data Types

Some basic data structures are built into programming languages: int, float, double, string. These are primitive types — they directly map to how data is stored in memory.

Abstract Data Types (ADTs) like Stack, Queue, and Tree describe operations and behavior without specifying implementation. The same ADT can be implemented in multiple ways — for example, a Stack can use an array or a linked list.

ADT Operations

Each ADT defines a set of allowed operations. For a Stack:

  • push(x) — Add element x to the top of the stack
  • pop() — Remove and return the top element
  • peek() — View the top element without removing it
  • isEmpty() — Check if the stack has no elements

Data Structure Operations

Insertion

Adding a new data element into a structure at a specified position.

Deletion

Removing an existing element from the structure.

Traversal

Accessing each element exactly once (e.g. printing all elements).

Searching

Finding the location of a given element in the structure.

Sorting

Arranging elements in a specific order (ascending or descending).

Merging

Combining elements of two sorted structures into one sorted structure.

Why DSA Matters

Time-Space Tradeoff: Often, you can reduce time complexity by using more memory, or reduce memory usage at the cost of slower execution. Choosing the right data structure is about finding the best balance for your use case.
Complexity Analysis

Asymptotic notations help us describe how algorithm performance scales with input size — without worrying about machine-specific details.

Why Complexity Analysis?

An algorithm's time depends on input size n. For larger inputs, some algorithms become impractically slow. We analyze worst-case and average-case complexity to predict behavior as n → ∞. This is called asymptotic analysis.

The Three Notations

Big O — Upper Bound

f(n) is O(g(n)) if there exist constants n₀, K > 0 such that f(n) ≤ K·g(n) for all n ≥ n₀.

→ Worst-case guarantee. Used most commonly.

Omega Ω — Lower Bound

f(n) is Ω(g(n)) if there exist n₀, K > 0 such that f(n) ≥ K·g(n) for all n > n₀.

→ Best-case guarantee.

Theta Θ — Tight Bound

f(n) is Θ(g(n)) if it is both O(g(n)) and Ω(g(n)).

→ Exact asymptotic behavior. Strongest statement.

Worst Case vs Average Case

Worst Case: The maximum time an algorithm takes for input of size n. This is the most commonly used measure — it gives us a guarantee.

Average Case: Expected time for a random input of size n. Often harder to compute but more realistic.
Linear Search

A sequential search algorithm that checks each element one by one until a match is found or the list ends.

How It Works

Linear search starts at index 0 and compares each element with the target. If a match is found, the index is returned. If the end of the array is reached without a match, the element is not present.

  • Set i = 1 (start at the beginning)
  • If i > n, go to step 7 (not found)
  • If A[i] == x, go to step 6 (found!)
  • Increment i = i + 1
  • Go back to step 2
  • Print "Element found at index i" → Exit
  • Print "Element not found" → Exit

Binary Search

A fast search algorithm that works on sorted arrays by repeatedly halving the search interval.

Key Idea

Binary search uses the fact that the array is sorted. By comparing the target with the middle element, we can eliminate half the search space in each step — giving us O(log n) complexity.

Step-by-Step Algorithm

  • Start with low = 0, high = n-1
  • Compute mid = (low + high) / 2
  • If arr[mid] == target → return mid (found!)
  • If target > arr[mid] → low = mid + 1 (search right half)
  • If target < arr[mid] → high = mid - 1 (search left half)
  • Repeat steps 2–5 until low > high (not found)

Pseudocode — Iterative Method

binarySearch(arr, x, low, high)
  repeat until low == high
    mid = (low + high) / 2
    if x == arr[mid]
      return mid
    else if x > arr[mid]   // x on right side
      low = mid + 1
    else                   // x on left side
      high = mid - 1

Complexity Analysis

CaseScenarioTime Complexity
BestTarget is the middle elementO(1)
AverageTarget found after a few halvingsO(log n)
WorstTarget is last element or not presentO(log n)
Why O(log n)? Each step halves the search space: n → n/2 → n/4 → ... → 1. After k steps, n/2ᵏ = 1, so k = log₂n steps maximum.
Stack (ADT)

A linear data structure following LIFO (Last In, First Out) — like a pile of plates. Only the top element is accessible.

Core Concept

A stack is implemented using arrays or linked lists. All insertions (push) and deletions (pop) happen at one end called the TOP. A pointer called TOP tracks the topmost element. Initially TOP = -1 (empty stack).

push()

Increment TOP, place new element at stack[TOP]. Check for overflow before pushing.

pop()

Return stack[TOP] and decrement TOP. Check for underflow before popping.

peek()

Return stack[TOP] without modifying TOP.

isEmpty()

Returns true if TOP == -1.

isFull()

Returns true if TOP == MAXSIZE - 1.

Applications of Stack

Expression Conversion

Converting infix expressions (A+B) to postfix (AB+) or prefix (+AB).

Expression Evaluation

Evaluating postfix/prefix expressions using a stack to hold operands.

Function Call Stack

Every function call pushes a frame; returning pops it.

Undo/Redo

Text editors maintain an undo stack of operations.

Complexity: Push, Pop, and Peek are all O(1) — the stack only accesses the top element, so no traversal is needed.
Queue (ADT)

A linear structure following FIFO (First In, First Out) — like people waiting in a queue. Insert at REAR, delete from FRONT.

Types of Queues

Simple Queue

Basic FIFO. Insert at rear, delete from front. Problem: wasted space after deletions.

Circular Queue

Last element connected to first — forms a ring. Solves wasted space using modulo arithmetic.

Priority Queue

Each element has a priority. Higher priority elements are served first, regardless of arrival order.

Circular Queue — How It Works

A normal queue wastes space after elements are dequeued. The circular queue solves this by treating the array as circular using modulo:

// Circular enqueue
if (REAR + 1) % SIZE == FRONT
  print "Queue is full"
else
  REAR = (REAR + 1) % SIZE
  queue[REAR] = data

Priority Queue

In a priority queue, elements are served based on their priority value, not arrival order. Elements with equal priority are served in FIFO order. Best implemented using a heap data structure.

Applications: CPU task scheduling, call center phone systems (queues), handling real-time system interrupts (first come, first served), printer job queues.
Linked List

A linear data structure where elements (nodes) are stored at non-contiguous memory locations, linked via pointers.

Node Structure

Each node contains two parts: Data (the value stored) and Next (a pointer/reference to the next node). The last node's Next pointer is NULL.

Singly Linked List
Interactive linked list — add and delete nodes

Types of Linked Lists

Singly Linked List

Each node points to the next. Traversal is unidirectional (head → tail). Most basic type.

Doubly Linked List

Each node has both Next and Prev pointers. Traversal in both directions. Needs extra memory.

Circular Linked List

Last node's Next points back to the Head. Forms a cycle. Useful in round-robin scheduling.

Circular Doubly

Combination — doubly linked and circular. Most flexible, most complex.

Operations on Linked List

  • Add to beginning: Allocate new node → Store data → Set new.next = head → Set head = new node
  • Add to end: Allocate new node → Traverse to last node → Set last.next = new node
  • Add to middle: Traverse to position → Update pointers to include new node between existing nodes
  • Delete from beginning: Set head = head.next → Free old head
  • Delete from end: Traverse to second-last → Set its next = NULL
  • Delete from middle: Traverse to node before target → Update pointer to skip target node
Trees — Basic Properties

A non-linear, hierarchical data structure — unlike arrays and linked lists which are linear and have only one path through them.

Why Non-Linear?

Tree data is arranged on multiple levels (hierarchy). Each node can have multiple children. There is exactly one path from the root to any other node.

Key Terminology

Root Node

Topmost node, no parent. Every non-empty tree has exactly one root.

Parent Node

A node that has one or more children. B is the parent of D and E.

Child Node

Immediate successor of a parent. D and E are children of B.

Leaf Node

External node with no children. Also called a terminal node.

Sibling

Children of the same parent. D and E are siblings.

Subtree

A node and all its descendants form a subtree.

Depth

Number of edges from root to that node. Root has depth 0.

Height

Longest path from node to any leaf. Height of tree = height of root.

Degree

Number of children a node has. Degree of a leaf = 0.

Tree Traversals

Unlike linear structures, trees can be traversed in different ways. The three standard traversals for binary trees:

Inorder (LNR)

1. Traverse left subtree
2. Visit root node
3. Traverse right subtree

For BST: gives elements in sorted order!

Preorder (NLR)

1. Visit root node
2. Traverse left subtree
3. Traverse right subtree

Used to copy a tree structure

Postorder (LRN)

1. Traverse left subtree
2. Traverse right subtree
3. Visit root node

Used to delete a tree

Properties: A tree with N nodes has exactly N-1 edges. There is only one path between any two nodes.
Binary Search Tree (BST)

A binary tree where: left child < parent < right child. This ordering enables efficient search, insert, and delete operations.

BST Property

For every node N in a BST: all values in the left subtree are less than N, and all values in the right subtree are greater than N. This property holds recursively for all subtrees.

Important: BST does not allow duplicate values. Binary Tree allows duplicates, BST does not.

BST Operations

Search

Compare target with root. If less → go left. If greater → go right. Repeat until found or NULL.

Insertion

Always inserted at a leaf. Navigate left/right until an empty spot is found, then insert.

Deletion (Leaf)

Simply set parent's pointer to NULL and free the node.

Deletion (One Child)

Replace node with its child. Parent now points directly to grandchild.

Deletion (Two Children)

Replace with inorder successor (smallest in right subtree) or inorder predecessor.

Sorting is arranging elements in a specific order. Different algorithms suit different situations — understanding their trade-offs is crucial.

Bubble Sort

Repeatedly compare adjacent elements and swap if they're in the wrong order. Largest elements "bubble up" to the end each pass.

How It Works

In each pass, compare A[i] with A[i+1]. If A[i] > A[i+1], swap them. After each full pass, the largest unsorted element is in its correct position. After n-1 passes, the array is sorted.

Worst Case O(n²): When array is in reverse order — n(n-1)/2 comparisons needed.
Best Case O(n): When array is already sorted (with optimization flag).
Selection Sort

Find the minimum element in the unsorted portion and place it at the beginning. Repeat for remaining elements.

How It Works

For position i from 0 to n-1: find the index of minimum value in arr[i..n-1], then swap arr[i] with that minimum. After each iteration, the sorted portion grows by one element.

for i = 0 to n-2:
  min_idx = i
  for j = i+1 to n-1:
    if arr[j] < arr[min_idx]:
      min_idx = j
  swap(arr[i], arr[min_idx])
Always O(n²): Selection sort makes n(n-1)/2 comparisons regardless of input order — even if already sorted. Makes minimum number of swaps (O(n)).
Insertion Sort

Build a sorted portion one element at a time by inserting each new element into its correct position in the sorted portion.

How It Works

Think of sorting playing cards. You pick each card and slide it into its correct position among the already-sorted cards in your hand.

Best for nearly-sorted arrays: When data is nearly sorted, insertion sort approaches O(n). Used in practice for small arrays (n < 20) and as a subroutine in more complex sorts.
Merge Sort

Divide and Conquer — recursively split the array in half, sort each half, then merge the two sorted halves.

How It Works

  • If array has 0 or 1 element, it's already sorted (base case)
  • Divide array into two halves at midpoint
  • Recursively sort the left half
  • Recursively sort the right half
  • Merge the two sorted halves into one sorted array
Merge Sort — Divide and Merge
[38, 27, 43, 3, 9, 82, 10]
[38, 27, 43] | [3, 9, 82, 10]
[38][27, 43] | [3, 9][82, 10]
↓ Sort ↓
[27, 38, 43] + [3, 9, 10, 82]
→ [3, 9, 10, 27, 38, 43, 82]
Guaranteed O(n log n): Unlike Quicksort, Merge Sort's worst case is always O(n log n). Downside: requires O(n) extra space for merging.
Heap Sort

Uses a Max-Heap data structure. Build a heap, then repeatedly extract the maximum to sort the array.

What is a Max-Heap?

A complete binary tree where every parent node is greater than or equal to its children. The root always contains the maximum element.

Heap Sort Steps

  • Build a max-heap from the input array — O(n)
  • The maximum element is at the root (index 0)
  • Swap root with the last element of the heap
  • Reduce heap size by 1 (the last element is now sorted)
  • Heapify the root to restore the max-heap property
  • Repeat steps 3–5 until heap size is 1
Heap Sort Example — arr = {4, 10, 3, 5, 1}
Step 1 — Build Max-Heap: [4,10,3,5,1] → [10,5,3,4,1]
Step 2 — Swap root(10) with last(1): [1,5,3,4, | 10]
Step 3 — Heapify → [5,4,3,1,|10], swap root(5) with last(1): [1,4,3,|5,10]
Continue until: [1, 3, 4, 5, 10] ✓ Sorted!
O(N log N) always: Building heap is O(n). Each extraction + heapify is O(log n), done n times. Total: O(n log n). Space: O(1) — sorts in-place!
Introduction to Graphs

A non-linear data structure consisting of vertices (nodes) connected by edges (arcs). G = (V, E) where V = vertices, E = edges.

Graph Terminology

Vertex / Node

Individual data element of a graph. In G = (V,E), A, B, C, D are vertices.

Edge / Arc

Connection between two vertices. Represented as (A, B) — a link from A to B.

Degree

Total number of edges connected to a vertex.

Indegree

Number of incoming edges to a vertex (directed graphs).

Outdegree

Number of outgoing edges from a vertex (directed graphs).

Path

A sequence of alternate vertices and edges from one vertex to another.

Adjacent

Two vertices are adjacent if there is a direct edge between them.

Self-loop

An edge where both endpoints are the same vertex.

Types of Graphs

Undirected Graph

Edges have no direction. If edge (A,B) exists, you can go from A→B and B→A.

Directed Graph (Digraph)

Edges have direction. Edge (A,B) means A→B only, not B→A.

Weighted Graph

Each edge has a weight/cost associated with it (e.g. road distances).

Simple Graph

No parallel edges, no self-loops.

BFS & DFS Graph Traversals

Two fundamental strategies to visit all vertices in a graph — both essential for solving graph problems.

BFS — Breadth-First Search

Visit all neighbors of a vertex before going deeper. Uses a Queue. Explores level by level.

Application: Shortest path in unweighted graphs

DFS — Depth-First Search

Go as deep as possible before backtracking. Uses a Stack (or recursion). Explores branch by branch.

Application: Cycle detection, topological sort

BFS Algorithm

  • Start at source vertex, mark it visited, add to Queue
  • While Queue is not empty: dequeue a vertex v
  • Visit all unvisited neighbors of v
  • Mark each neighbor visited and enqueue it
  • Repeat until Queue is empty

DFS Algorithm

  • Start at root/arbitrary node, mark it visited
  • Move to an adjacent unvisited node, mark it visited
  • Continue until no unvisited adjacent nodes exist
  • Backtrack to the previous node, check for other unvisited neighbors
  • Repeat until all nodes are visited
Key Difference: BFS uses a Queue → explores in rings outward from source. DFS uses a Stack → goes deep into one branch before trying others.

Complexity (both): Time O(V+E), Space O(V) where V = vertices, E = edges.
