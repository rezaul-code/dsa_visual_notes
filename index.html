Introduction to Data Structures
A data structure is a way of organizing and storing data in memory so that it can be accessed and modified efficiently. Choosing the right data structure is the foundation of efficient programming.

What is a Data Structure?

A data structure is a method of arrangement in memory to hold data associated with objects to facilitate access and various operations on that data. Think of it like a container — different containers suit different purposes.

Real World Analogy

📚 A library organizes books on shelves (arrays). A stack of plates in a cafeteria (stack). A queue at a ticket counter (queue). A family tree (tree structure). Each organizes information differently for efficient access.

Classification of Data Structures

Core Operations on Data Structures

Insertion

Adding a new data element into a data structure at a given position.

Deletion

Removing an existing element from the data structure.

Traversal

Accessing each data element exactly once to process it (e.g., print all).

Searching

Finding the location of a given data element in the structure.

Sorting

Arranging elements in a defined order: ascending or descending.

Merging

Combining two sorted structures into a single sorted structure.

Why Do We Need Data Structures?

Without proper data structures:

  • Searching 1 million records takes O(n) = slow
  • Inserting into sorted array shifts all elements
  • Memory is wasted on inefficient storage

With right data structure:

  • Hash table lookup: O(1) average
  • BST insertion: O(log n)
  • Heap find-max: O(1)
Time-Space Tradeoff: Often you can reduce time at the cost of more memory, or save memory at the cost of slower execution. Choosing the right data structure means finding the best balance for your problem.

🟢 Beginner — P1: Count Elements

Problem

Given an array of integers, count how many elements are greater than a given value X.

// Input:  arr = [3, 7, 1, 9, 4, 6], X = 5
// Output: 3  (elements 7, 9, 6 are > 5)

countGreater(arr, n, X):
  count = 0
  for i = 0 to n-1:
    if arr[i] > X:
      count = count + 1
  return count

// Time: O(n) — visit every element once
// Space: O(1) — only one counter variable

🟡 Intermediate — P2: Find Second Largest

Problem

Find the second largest element in an array without sorting it. Handle duplicates.

// Input:  arr = [12, 35, 1, 10, 34, 1]
// Output: 34

secondLargest(arr, n):
  if n < 2: return -1
  first  = -∞
  second = -∞
  for i = 0 to n-1:
    if arr[i] > first:
      second = first       // old first drops to second
      first  = arr[i]
    elif arr[i] > second and arr[i] != first:
      second = arr[i]
  if second == -∞: return -1  // all elements equal
  return second

// Time: O(n) — single pass
// Space: O(1)

🔴 Microsoft-Level — P3: Majority Element

Problem (Boyer-Moore Voting Algorithm)

Find the element that appears more than ⌊n/2⌋ times. Must be O(n) time and O(1) space — no hash map allowed.

// Input:  arr = [2, 2, 1, 1, 1, 2, 2]
// Output: 2  (appears 4 times > 7/2 = 3.5)

majorityElement(arr, n):
  // Phase 1: Find candidate
  candidate = arr[0]
  count = 1
  for i = 1 to n-1:
    if count == 0:
      candidate = arr[i]
      count = 1
    elif arr[i] == candidate:
      count = count + 1
    else:
      count = count - 1

  // Phase 2: Verify candidate
  freq = 0
  for i = 0 to n-1:
    if arr[i] == candidate: freq++
  if freq > n/2: return candidate
  return -1  // no majority element

// Key insight: majority element "cancels out"
// all other elements combined — last standing wins
// Time: O(n)  Space: O(1)
Pattern to remember: Most array problems at Microsoft use one of: single pass with variables, two pointers, or prefix sums. Always ask — can I do this in O(n) time and O(1) space?
Abstract Data Types (ADT)
An ADT defines what operations can be performed on data, without specifying how those operations are implemented internally.

ADT vs Data Structure

Abstract Data Type (ADT)

A logical description. Defines operations and behavior only. Like a blueprint or interface.

Example: A "Stack" ADT says you can push, pop, and peek — but doesn't say how.

Data Structure

The actual implementation of an ADT in code using memory. The concrete realization.

Example: A Stack implemented using an array in C++.

Key Insight

A Stack ADT can be implemented using an array OR a linked list. The ADT (the "what") stays the same, only the implementation (the "how") changes. This is the power of abstraction.

The Halting Problem

Important: Not all computational problems have an algorithm. The Halting Problem — determining whether a program will halt or loop forever for any given input — is a classic example of a problem with no algorithm. Also, some problems may have multiple algorithms — like sorting (bubble, merge, heap...).

Algorithm Properties

An algorithm must have:

Input

Zero or more inputs from a specified set.

Output

At least one output is produced.

Definiteness

Each step is clear and unambiguous.

Finiteness

Must terminate after a finite number of steps.

Effectiveness

Each step must be basic enough to be executed.

🟡 Intermediate — P2: Stack using Two Queues

Problem

Implement a Stack ADT using only Queue operations. No array/linked-list directly.

// Use two queues Q1 and Q2
// Key idea: on every push, make Q1 hold
// elements in LIFO order

push(x):
  enqueue(Q2, x)              // Step 1: add x to Q2
  while Q1 not empty:        // Step 2: move all Q1 → Q2
    enqueue(Q2, dequeue(Q1))
  swap(Q1, Q2)                // Step 3: Q1 now has stack order

pop():
  if Q1 empty: return error
  return dequeue(Q1)         // Front of Q1 = top of stack

// Trace: push(1), push(2), push(3)
// After push(1): Q1=[1]
// After push(2): Q2=[2], move Q1→Q2=[2,1], swap → Q1=[2,1]
// After push(3): Q1=[3,2,1]
// pop() → dequeue Q1 → returns 3 ✅ LIFO!

// Time: push O(n), pop O(1)

🔴 Microsoft-Level — P3: Design LRU Cache ADT

Problem (Classic Microsoft/Google Interview)

Design an LRU (Least Recently Used) Cache ADT with capacity k. Support get(key) and put(key, value) both in O(1).

// ADT Contract:
// get(key)        → return value if exists, else -1
// put(key, value) → insert/update; if at capacity,
//                   evict least recently used item

// Implementation uses:
// 1. HashMap  → O(1) key lookup
// 2. Doubly Linked List → O(1) insert/delete anywhere

Structure Node: {key, value, prev, next}
Structure LRUCache: {capacity, map, head, tail}

get(key):
  if key not in map: return -1
  node = map[key]
  moveToFront(node)      // mark as recently used
  return node.value

put(key, value):
  if key in map:
    map[key].value = value
    moveToFront(map[key])
  else:
    if size == capacity:
      lru = removeTail()       // evict LRU
      delete map[lru.key]
    newNode = Node(key, value)
    addToFront(newNode)        // most recently used
    map[key] = newNode

// HEAD ↔ [most recent] ↔ ... ↔ [least recent] ↔ TAIL
// Time: O(1) for both get and put
// Space: O(capacity)
Interview tip: When asked to "design" something, always state the ADT first (what operations, what guarantees) before jumping to implementation. Interviewers reward structured thinking.
Complexity Analysis
Complexity analysis predicts the computing resources (time and memory) an algorithm consumes, as a function of input size n.

Why Analyze Complexity?

The time taken by an algorithm depends on input size n. For the same n, different inputs may cause different running times. We define:

Worst-Case Complexity

Maximum time for input of size n. Gives a guarantee — it will never be slower than this. Most commonly used in analysis.

Average-Case Complexity

Expected time for a random input of size n. More realistic but harder to compute. Used for probabilistic analysis.

Problem

fib(n):
  if n <= 1: return n
  return fib(n-1) + fib(n-2)

// Recurrence: T(n) = T(n-1) + O(1)
// → O(n)  n recursive calls, O(1) each

🔴 Microsoft-Level — P3: Optimize the Solution

Problem

Given a sorted array, find all pairs that sum to a target value. Improve from O(n²) brute force to O(n).

// Input:  arr = [1, 2, 3, 4, 6, 8, 9], target = 10
// Output: (1,9), (2,8), (4,6)

// ❌ Brute Force — O(n²)
pairsBrute(arr, n, target):
  for i = 0 to n-1:
    for j = i+1 to n-1:
      if arr[i] + arr[j] == target:
        print(arr[i], arr[j])

// ✅ Two Pointer — O(n)  uses sorted property!
pairsTwoPtr(arr, n, target):
  left  = 0
  right = n - 1
  while left < right:
    s = arr[left] + arr[right]
    if s == target:
      print(arr[left], arr[right])
      left++; right--
    elif s < target:
      left++          // need bigger sum
    else:
      right--         // need smaller sum

// Complexity improvement:
// Brute:     O(n²) time, O(1) space
// Two Ptr:   O(n)  time, O(1) space  ← optimal!
// Hash Set:  O(n)  time, O(n) space  ← also valid

Asymptotic Notations
Mathematical tools to describe the limiting behavior of a function when the argument tends towards infinity. Used to express algorithm complexity without machine-specific details.

The Three Notations

Big O — O(g(n))

f(n) is O(g(n)) if ∃ n₀, K > 0 such that f(n) ≤ K·g(n) for all n ≥ n₀.

Gives upper bound. Algorithm is at most this slow. Worst-case guarantee.

Omega — Ω(g(n))

f(n) is Ω(g(n)) if ∃ n₀, K > 0 such that f(n) ≥ K·g(n) for all n > n₀.

Gives lower bound. Algorithm is at least this fast. Best-case guarantee.

Theta — Θ(g(n))

f(n) is Θ(g(n)) if it is both O(g(n)) and Ω(g(n)).

Gives tight bound. The exact asymptotic behavior. Strongest statement you can make.

Calculating Big O — Rules

// Rule 1: Drop constants
f(n) = 3n  →  O(n)    // NOT O(3n)
f(n) = 100  →  O(1)   // constant time

// Rule 2: Drop lower-order terms
f(n) = n² + n + 1  →  O(n²)   // n dominates for large n
f(n) = n·log(n) + n  →  O(n log n)

// Rule 3: Nested loops = multiply
for(i=0; i<n; i++)        // O(n)
  for(j=0; j<n; j++)      // O(n)
    doWork();              // → O(n²)

// Rule 4: Sequential loops = add
for(i=0; i<n; i++) ...    // O(n)
for(j=0; j<n; j++) ...    // O(n)
// Total → O(n) + O(n) = O(n)
Interview tip: When asked "what is the time complexity?", always state Big O (worst case) unless specifically asked for best or average case.

Formally prove that f(n) = 4n² + 3n is O(n²) by finding constants c and n₀.

// Formal proof structure:
// Need to find c > 0 and n₀ ≥ 1 such that:
// f(n) ≤ c·g(n) for all n ≥ n₀

// f(n) = 4n² + 3n
// For n ≥ 1: 3n ≤ 3n²
// So: 4n² + 3n ≤ 4n² + 3n² = 7n²

// Therefore: f(n) ≤ 7·n² for all n ≥ 1
// → c = 7, n₀ = 1
// → f(n) = O(n²)  ✅ proven!

// Similarly prove Ω(n²):
// 4n² + 3n ≥ 4n² for all n ≥ 0
// → c = 4, n₀ = 0
// → f(n) = Ω(n²)  ✅
// Combined: f(n) = Θ(n²)  ✅

🔴 Microsoft-Level — P3: Amortized Analysis

Problem — Dynamic Array Amortized Cost

A dynamic array doubles in size when full. Show that n insertions cost O(n) total — meaning O(1) amortized per insertion — even though some insertions cost O(n).

// Scenario: start with capacity 1, double when full
// Cost of each insertion:

// Insert 1: capacity=1, no resize  → cost 1
// Insert 2: resize (copy 1 elem)   → cost 1+1 = 2
// Insert 3: resize (copy 2 elems)  → cost 2+1 = 3
// Insert 4: no resize              → cost 1
// Insert 5: resize (copy 4 elems)  → cost 4+1 = 5
// Insert 6,7,8: no resize          → cost 1 each
// Insert 9: resize (copy 8 elems)  → cost 8+1 = 9

// Total cost for n insertions:
// = n + (1 + 2 + 4 + 8 + ... + n/2)
// = n + n (geometric series sum ≈ 2n)
// = O(n)

// Amortized cost per insertion:
// = O(n) / n = O(1)  ✅

// This is why Python list.append() is O(1) amortized
// even though occasional resizes cost O(n)

// Banker's method intuition:
// Each insertion "saves" 1 credit for future resize
// When resize happens, saved credits pay for it
Amortized ≠ Average: Average case assumes random input. Amortized is a worst-case guarantee spread over a sequence of operations. Dynamic arrays, union-find, and splay trees all use amortized analysis.
Arrays
An array is a collection of elements of the same data type stored in contiguous memory locations. It is the most fundamental and widely-used data structure.

Memory Layout

Address formula: Address of arr[i] = BaseAddress + (i × sizeof(datatype))
So arr[3] = 0x100 + (3 × 4) = 0x10C — direct calculation, no traversal needed → O(1) access!

Linear Search
The simplest search algorithm — checks each element one by one from left to right until the target is found or the list ends. Works on unsorted arrays.

How It Works

  1. Start at index 0
  2. Compare current element with target
  3. If match → return the index (found!)
  4. If no match → move to next element
  5. If end of array → return -1 (not found)

Binary Search
A divide-and-conquer search on sorted arrays. Eliminates half the remaining elements with each comparison — achieving O(log n) time.

Key Insight

If the array is sorted and we check the middle element:

  • If middle == target → found!
  • If target < middle → target can only be in the left half
  • If target > middle → target can only be in the right half

Each step halves the search space: n → n/2 → n/4 → ... → 1. After k steps: n/2ᵏ = 1, so k = log₂n.

Iterative vs Recursive

Iterative Method

binarySearch(arr, x, low, high):
  while low <= high:
    mid = (low + high) / 2
    if arr[mid] == x:
      return mid
    elif x > arr[mid]:
      low = mid + 1
    else:
      high = mid - 1
  return -1

Recursive Method

binarySearch(arr, x, low, high):
  if low > high:
    return -1
  mid = (low + high) / 2
  if arr[mid] == x:
    return mid
  elif x > arr[mid]:
    return binarySearch(arr, x, mid+1, high)
  else:
    return binarySearch(arr, x, low, mid-1)

Complexity

CaseWhenComplexity

AverageTarget found after a few halvingsO(log n)
WorstTarget at boundary or not presentO(log n)
Prerequisite: Array MUST be sorted before applying binary search. Sorting costs O(n log n) so for a single search on unsorted data, linear search may be preferable.
Stack (LIFO)
A linear data structure where insertion and deletion happen at one end only — the TOP. Follows Last In, First Out (LIFO) principle.

Real-World Examples

🍽️ Pile of Plates

You add plates on top and remove from top. The last plate placed is the first one taken.

⬅️ Browser Back Button

Each page visited is pushed. Back button pops to previous page.

📝 Undo in Editor

Each action is pushed. Ctrl+Z pops and reverses the last action.

⚙️ Function Call Stack

Each function call is pushed. Return pops the frame.

Pseudocode

// PUSH — Add to top
procedure push(data):
  if top == MAXSIZE - 1:
    print "Stack Overflow!"
  else:
    top = top + 1
    stack[top] = data

// POP — Remove from top
procedure pop():
  if top == -1:
    print "Stack Underflow!"
  else:
    data = stack[top]
    top = top - 1
    return data

// PEEK — View top without removing
procedure peek():
  return stack[top]  // No modification

Applications of Stack

Expression Conversion

Infix → Postfix (Shunting Yard algorithm). Example: A+B*C → ABC*+

Expression Evaluation

Evaluate postfix: push operands, on operator pop two, compute, push result.

Balanced Parentheses

Check if brackets are balanced: push opening, pop on closing and verify match.

Function Call Stack

Each function call pushes activation record; return pops it. Stack overflow = too many recursive calls.

All Stack Operations are O(1) — Push, Pop, and Peek only access the TOP element. No traversal, no searching — constant time always.
Queue (FIFO)
An ordered list where insertion happens at REAR and deletion at FRONT. Follows First In, First Out (FIFO) principle.

Queue vs Stack

Queue (FIFO)

Like a line at a bank. First person to arrive is served first.
Insert at REAR, Delete from FRONT.

Stack (LIFO)

Like a stack of books. Last book placed is first removed.
Insert and Delete at TOP.

// ENQUEUE — Add at rear

  if rear == MAXSIZE - 1:
    print "Queue Overflow!"

  else:
    data = queue[front]
    front = front + 1
    return data

Applications of Queue

  • CPU Task Scheduling: Processes are queued and executed in order
  • Print Queue: Print jobs are handled FIFO
  • Keyboard Buffer: Keystrokes stored in queue order
  • BFS Graph Traversal: Uses queue to explore level-by-level
  • Call Center Systems: Customers wait in queue for agents
⚠️ Problem with Simple Queue: After several enqueue+dequeue operations, FRONT moves right and earlier positions become unusable — space is wasted even when queue isn't full. Solution: Circular Queue!
Circular Queue
An extension of a queue where the last position is connected back to the first, forming a circle (Ring Buffer). Solves wasted space in simple queue.

The Problem It Solves

Simple Queue Problem:
After enqueue 5 times then dequeue 3 times:
FRONT=3, REAR=4
Positions 0,1,2 are FREE but unusable!
Array looks "full" but has empty slots.
Circular Queue Solution:
When REAR reaches end, it wraps to index 0.
Uses modulo: REAR = (REAR + 1) % SIZE
All positions are reusable. No wasted space!

Circular Queue Visualization

How Circular Increment Works

// Circular increment using modulo
REAR = (REAR + 1) % SIZE   // Wrap to 0 when reaching end
FRONT = (FRONT + 1) % SIZE

// Example: SIZE=5, REAR=4
REAR = (4 + 1) % 5 = 0  // Wraps back to beginning!

// Queue is FULL when:
(REAR + 1) % SIZE == FRONT

// Queue is EMPTY when:
FRONT == -1

Tree Properties

No cycles

A tree has no loops. You cannot traverse back to a previously visited node (unlike graphs).

N-1 Edges

A tree with N nodes always has exactly N-1 edges. Proof: each node except root has exactly one parent edge.

One Path

There is exactly one path between any two nodes in a tree.

Connected

All nodes are reachable. Removing any edge disconnects the tree.

Why trees? Trees provide O(log n) operations (search, insert, delete) when balanced — much better than O(n) for linear structures. File systems, databases (B-trees), expression parsing, and decision trees all use tree structures.
Tree Traversals
Unlike linear structures that have only one way to traverse, trees can be visited in multiple orders. Each traversal serves different purposes.

The Three Standard Traversals

Inorder — Left → Root → Right

Visit left subtree, then root, then right subtree.

Result: 10, 15, 22, 25, 35, 50, 70
⭐ For BST: always gives sorted output!

Preorder — Root → Left → Right

Visit root first, then left subtree, then right subtree.

Result: 25, 15, 10, 22, 50, 35, 70
Used to copy/serialize a tree

Postorder — Left → Right → Root

Visit left, then right, then root last.

Result: 10, 22, 15, 35, 70, 50, 25
Used to delete a tree (bottom-up)

Pseudocode

// INORDER
procedure inorder(node):
  if node == null: return
  inorder(node.left)
  visit(node)
  inorder(node.right)
// PREORDER
procedure preorder(node):
  if node == null: return

  if node == null: return
  postorder(node.left)
  postorder(node.right)

All traversals are O(n) — every node is visited exactly once. Space complexity is O(h) where h = height (due to recursion stack). For balanced tree: O(log n), worst case O(n).
Binary Search Tree (BST)
A binary tree where every node satisfies: left subtree values < node value < right subtree values. This ordering enables O(log n) search, insert, delete.

BST Property Explained

The BST Invariant

For ANY node N in the tree:
• ALL values in left subtree are less than N.data
• ALL values in right subtree are greater than N.data
• This applies recursively to every subtree
• No duplicate values are allowed

BST Visualization — Insert 45, 15, 79, 90, 10, 55, 12, 20, 50

BST Search Algorithm

procedure search(root, target):
  if root == null: return null  // Not found
  if root.data == target: return root  // Found!
  if target < root.data:
    return search(root.left, target)   // Go LEFT
  else:
    return search(root.right, target)  // Go RIGHT

Deletion — Three Cases

Case 1: Leaf Node

Simplest case. Node has no children. Simply set parent's pointer to NULL and free the node.

Case 2: One Child

Replace the node with its child. Parent now points directly to the grandchild node.

Case 3: Two Children

Replace with inorder successor (smallest in right subtree). Then delete the successor from its original position.

Complexity Analysis

OperationAverage (Balanced)Worst (Degenerate)
SearchO(log n)O(n)
InsertO(log n)O(n)
DeleteO(log n)O(n)
⚠️ Degenerate BST: If elements are inserted in sorted order (1, 2, 3, 4, 5...), the BST becomes a linked list — every node has only a right child. All operations degrade to O(n). Solution: use a self-balancing BST like AVL Tree.
AVL Tree
A self-balancing BST that maintains a height difference of at most 1 between left and right subtrees of every node — guaranteeing O(log n) always.

Balance Factor

For every node: Balance Factor = Height(left) - Height(right)

An AVL tree requires Balance Factor ∈ {-1, 0, +1} for every node. If any node has |BF| = 2, the tree is unbalanced and must be rotated.

AVL Rotations

LL Rotation (Right Rotate)

Imbalance in left-left. Rotate right on the unbalanced node. Simple single rotation.

RR Rotation (Left Rotate)

Imbalance in right-right. Rotate left on the unbalanced node. Simple single rotation.

LR Rotation (Left-Right)

Left rotate child, then right rotate parent. Double rotation needed.

RL Rotation (Right-Left)

Right rotate child, then left rotate parent. Double rotation needed.

AVL vs BST Comparison

PropertyBSTAVL Tree
BalanceNot guaranteedAlways balanced (BF ∈ {-1,0,1})

InsertO(n) worst caseO(log n) + rotation overhead
Complexity of rotationsN/AO(1) per rotation
Use caseSimple lookupsFrequent search operations
Key insight: AVL trees maintain balance through rotations during every insert/delete. This ensures height is always O(log n), making all operations O(log n) guaranteed — unlike plain BST which can degrade to O(n).

Bubble Sort
Repeatedly compare adjacent pairs and swap if out of order. Largest elements "bubble up" to their correct position at the end after each pass.

How It Works

In each pass through the array, compare arr[i] with arr[i+1]. If arr[i] > arr[i+1], swap them. After pass 1, the largest element is at index n-1. After pass 2, second largest is at n-2. Continue for n-1 passes.

bubbleSort(arr, n):
  for i = 0 to n-2:
    swapped = false
    for j = 0 to n-2-i:
      if arr[j] > arr[j+1]:
        swap(arr[j], arr[j+1])
        swapped = true
    if !swapped: break   // Optimization: already sorted

Selection Sort
Find the minimum element in the unsorted portion and swap it to the current position. Builds sorted array from left to right.

How It Works

Divide array into: sorted portion (left) and unsorted portion (right). In each iteration, find the minimum in the unsorted portion and swap it with the first element of the unsorted portion.

Pseudocode

selectionSort(arr, n):
  for i = 0 to n-2:
    min_idx = i
    for j = i+1 to n-1:
      if arr[j] < arr[min_idx]:
        min_idx = j
    if min_idx != i:
      swap(arr[i], arr[min_idx])

Pass 3: Min in [25,22,64] = 22 → Swap → [11,12,22,25,64]
Pass 4: Min in [25,64] = 25 (no swap) → [11,12,22,25,64] ✅
O(n²) always — makes exactly n(n-1)/2 comparisons regardless of input. But makes minimum number of swaps: O(n). Good when write operations are expensive.
Insertion Sort
Build a sorted portion by inserting each new element into its correct position in the already-sorted portion — like sorting playing cards in hand.

Mental Model

insertionSort(arr, n):
  for i = 1 to n-1:
    key = arr[i]        // Element to insert
    j = i - 1
    while j >= 0 and arr[j] > key:
      arr[j+1] = arr[j]  // Shift right
      j = j - 1
    arr[j+1] = key      // Insert key

Merge Sort
Divide and Conquer — recursively split array in half, sort each half, then merge the two sorted halves. Guarantees O(n log n) always.

Three Steps

2. Conquer: Recursively sort each half
3. Combine: Merge two sorted halves into one sorted array

The Merge Function

merge(arr, left, mid, right):
  // Create temp arrays for left and right halves
  L = arr[left..mid]
  R = arr[mid+1..right]
  i = j = 0
  k = left
  while i < len(L) and j < len(R):
    if L[i] <= R[j]:
      arr[k] = L[i]; i++
    else:
      arr[k] = R[j]; j++
    k++
  // Copy remaining elements
  while i < len(L): arr[k++] = L[i++]
  while j < len(R): arr[k++] = R[j++]

Why O(n log n)?

log n levels

Splitting n elements in half repeatedly: n → n/2 → n/4 → ... → 1 takes log₂n levels.

O(n) per level

Merging all elements at each level requires exactly n comparisons total across all merges at that level.

Total = O(n) × O(log n) = O(n log n) — always! Unlike Quicksort, Merge Sort's worst case is also O(n log n). Downside: requires O(n) extra space for temp arrays.
Heap Sort
Uses a Max-Heap data structure. Build a max-heap, then repeatedly extract the maximum to build the sorted array. In-place, O(n log n) always.

What is a Heap?

Max-Heap

A complete binary tree where every parent ≥ both children. The root always has the maximum element. This is what Heap Sort uses.

Min-Heap

A complete binary tree where every parent ≤ both children. The root always has the minimum element. Used in priority queues and Dijkstra's.

Heap Sort Steps

  1. Build Max-Heap from input array → O(n)
  2. Root (index 0) contains the maximum element
  3. Swap root with last element of heap
  4. Reduce heap size by 1 (last element is now in correct position)
  5. Heapify the root to restore max-heap property → O(log n)
  6. Repeat steps 2–5 until heap size = 1

Example — arr = {4, 10, 3, 5, 1}

Build Heap: [4,10,3,5,1] → [10, 5, 3, 4, 1] (max-heap)
Step 1: Swap 10 and 1 → [1,5,3,4, | 10✓] → heapify → [5,4,3,1]
Step 2: Swap 5 and 1 → [1,4,3, | 5,10✓] → heapify → [4,1,3]
Step 3: Swap 4 and 3 → [3,1, | 4,5,10✓] → heapify → [3,1]
Step 4: Swap 3 and 1 → [1 | 3,4,5,10✓]
Result: [1, 3, 4, 5, 10] ✅

Heapify Function

heapify(arr, n, root):
  largest = root
  left = 2*root + 1     // Left child index
  right = 2*root + 2    // Right child index
  if left < n and arr[left] > arr[largest]:
    largest = left
  if right < n and arr[right] > arr[largest]:
    largest = right
  if largest != root:
    swap(arr[root], arr[largest])
    heapify(arr, n, largest)  // Recursively heapify subtree
O(N log N) always + O(1) space: Building heap is O(n). Each of the n extractions requires O(log n) heapify. Total O(n log n). Unlike Merge Sort, no extra space needed — sorts in-place!

BFS & DFS Graph Traversals
Two fundamental strategies to visit all vertices. BFS uses a Queue, explores level-by-level. DFS uses a Stack, goes deep before backtracking.

BFS vs DFS at a Glance

BFS — Breadth-First Search

Explore all neighbors of a vertex before going deeper. Uses a Queue (FIFO). Explores ring by ring from source.

Best for: Shortest path in unweighted graph

DFS — Depth-First Search

Go as deep as possible before backtracking. Uses a Stack (LIFO) or recursion. Explores one branch fully before another.

Best for: Cycle detection, topological sort, connected components

BFS Visual Example

BFS Algorithm

BFS(graph, start):
  visited = set()
  queue = Queue()
  visited.add(start)
  queue.enqueue(start)
  while queue is not empty:
    vertex = queue.dequeue()
    print(vertex)
    for neighbor in graph[vertex]:
      if neighbor not in visited:
        visited.add(neighbor)
        queue.enqueue(neighbor)

DFS Algorithm

DFS(graph, vertex, visited):
  visited.add(vertex)
  print(vertex)
  for neighbor in graph[vertex]:
    if neighbor not in visited:
      DFS(graph, neighbor, visited)  // Recursive!

// Iterative DFS using explicit stack:
DFS_iterative(graph, start):
  stack = Stack()
  stack.push(start)
  while stack not empty:
    v = stack.pop()
    if v not in visited:
      visited.add(v); print(v)
      for n in graph[v]: stack.push(n)

Hashing
A technique to map keys to array indices using a hash function — enabling O(1) average-case search, insert, and delete operations.

The Core Idea

Instead of searching through all elements (O(n)), use a hash function to compute directly where the element should be stored: index = hash(key) % table_size

Hash Collision

When two different keys map to the same index, it's called a collision. Two main ways to resolve:

Chaining (Open Hashing)

Each slot holds a linked list. Colliding elements are added to the chain at that index.

✅ Never full, simple to implement

❌ Extra memory for pointers

Open Addressing

Find next available slot using probing (linear, quadratic, double hashing).

✅ Cache-friendly, no pointers

❌ Table can get full, clustering

Complexity

OperationAverage CaseWorst Case
SearchO(1)O(n) (all keys collide)
InsertO(1)O(n)
DeleteO(1)O(n)
Load Factor = n/m where n = elements, m = table size. Keep load factor below 0.7 for good performance. When exceeded, rehash (double table size and re-insert all).

Applications

  • Hash Maps / Dictionaries: Python dict, Java HashMap, C++ unordered_map
  • Database indexing: Fast lookup of records
  • Caching: Store recently computed values
  • Deduplication: Check if element already seen in O(1)
